# Architecture Decision Records

이 디렉터리는 프로젝트의 중요한 구조적 결정을 기록합니다. ADR은 구현 방법을 나열하기보다, 왜 해당 결정을 내렸는지와 그 결과를 남기는 문서입니다.

## 언제 작성하는가

다음처럼 나중에 되돌리기 어렵거나 여러 기능에 영향을 주는 결정에 작성합니다.

- 데이터 모델이나 저장소 구조를 바꾸는 경우
- 인증·권한·세션 전략을 정하는 경우
- 외부 API나 서비스 연동 방식을 정하는 경우
- 여러 화면과 모듈이 공유하는 계산·상태 관리 방식을 정하는 경우

단순한 UI 수정, 버그 수정, 포맷팅, 일회성 리팩터링에는 작성하지 않습니다.

## 파일명과 상태

파일명은 `NNNN-short-title.md` 형식을 사용합니다. 번호는 기존 문서의 마지막 번호 다음으로 지정합니다.

상태는 다음 중 하나를 사용합니다.

- `Proposed`: 검토 중인 결정
- `Accepted`: 현재 적용 중인 결정
- `Superseded`: 더 새로운 ADR로 대체된 결정
- `Deprecated`: 더 이상 유효하지 않은 결정

기존 ADR은 삭제하지 않습니다. 결정이 바뀌면 기존 문서의 상태를 `Superseded`로 바꾸고 대체 ADR을 연결합니다.

## 템플릿

```md
# ADR-NNNN: 결정 제목

- 상태: Proposed | Accepted | Superseded | Deprecated
- 날짜: YYYY-MM-DD
- 대체 문서: ADR-NNNN (해당하는 경우)

## Context

어떤 문제와 제약이 있었는지 작성합니다.

## Decision

무엇을 선택했는지 명확하게 작성합니다.

## Alternatives

검토했지만 선택하지 않은 대안과 선택하지 않은 이유를 작성합니다.

## Consequences

이 결정의 장점, 단점, 운영·개발상 영향을 작성합니다.
```

문서 하나에는 하나의 결정만 기록하고, 구현 세부사항보다 선택의 이유와 영향에 집중합니다.
