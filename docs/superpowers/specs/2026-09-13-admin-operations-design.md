# 관리자 운영 화면 설계

## 목표

일반 사용자 화면과 분리된 `/admin` 영역에서 문의 처리와 주간 실거래 자동수집 상태를 관리한다. 사용자가 남긴 문의는 앱에만 저장하고, 관리자가 개발 작업이 필요하다고 판단한 문의만 GitHub Issue로 전송한다. 사용자에게는 내부 구현이나 보안 정보를 포함하지 않은 오류만 보여주며 상세 원인은 Vercel 서버 로그에서 추적한다.

## 권한과 화면

관리자는 Supabase Auth 이메일·비밀번호 계정으로 `/admin/login`에서 로그인한다. `app_admins.user_id`에 등록된 계정만 관리자 API와 `/admin` 데이터에 접근한다. 관리자 화면은 문의와 자동수집 두 메뉴를 제공하고 로그아웃을 지원한다.

문의 목록은 상태·유형·GitHub 전송 상태 필터와 검색을 제공한다. 상세 화면은 최초 문의, 후속 메시지, 첨부 이미지를 시간순으로 보여준다. 관리자는 답변과 상태 변경을 수행하고, 필요한 문의만 제목과 본문을 검토한 뒤 GitHub Issue로 전송한다. 이미 연결된 문의는 중복 전송하지 않는다. 이후 사용자 메시지는 GitHub로 자동 전송하지 않는다.

자동수집 화면은 최근 실행의 시작·완료 시각, 실행 주체, 처리 단지 수, 저장 거래 수, 실패 수와 안전하게 정리된 실패 대상을 표시한다. `running`, `success`, `partial`, `failed` 상태를 사용하고, 예약 시각을 지났는데 최근 실행이 없으면 `delayed`로 화면에서 계산한다. 관리자는 수동 실행과 실패 후 재실행을 할 수 있으며, 실행 중인 작업이 있으면 중복 실행하지 않는다.

## 데이터와 API

`trade_sync_runs` 테이블에 실행 이력을 저장한다. 상세 외부 오류 원문은 저장하지 않고 서버 로그에만 기록한다. 관리자 API는 문의 목록·상세·답변·GitHub 전송과 수집 이력·수동 실행을 제공한다. 예약 실행과 관리자 수동 실행은 같은 수집 함수를 호출한다.

API 오류 응답은 `{ error, requestId }` 형태를 사용한다. 사용자에게는 인증, 입력 검증, 재시도 여부처럼 행동 가능한 정보만 반환한다. 서버 로그에는 `requestId`, 작업명, 안전한 식별자, 원래 오류를 기록하되 토큰, 쿠키, API 키, 문의 원문과 이미지 데이터는 기록하지 않는다.

## 검증

문의 생성과 후속 메시지가 GitHub를 호출하지 않는지, 관리자만 이슈를 생성할 수 있는지, 중복 생성이 거부되는지 검증한다. 자동수집 상태 계산과 중복 실행 방지를 검증한다. 공개 API가 내부 오류 메시지를 반환하지 않는지 검사하고 전체 테스트와 프로덕션 빌드를 실행한다.
